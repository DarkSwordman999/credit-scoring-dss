# Руководство администратора

## Варианты установки

| Вариант | Для чего | Состав |
|---|---|---|
| Windows-версия | демонстрация, обучение, небольшой отдел | один процесс, SQLite в папке `data` |
| Docker Compose | внутренний контур Банка (ПР 7-8, диаграмма размещения) | PostgreSQL 16, backend-api, сервис скоринга, планировщик, nginx, прокси Caddy для HTTPS |
| Из исходников | разработка | Python 3.12, Node.js 22 |

### Windows

Скачайте `CreditDSS-<версия>-windows-x64.zip` со страницы Releases, распакуйте и запустите `КредитныйСкоринг.exe`. Подробности — в `README.txt` архива.

### Docker Compose

```
cd deploy
cp .env.example .env            # задайте DB_PASSWORD, SCORING_KEY и при необходимости остальное
docker compose up -d --build
docker compose exec api creditdss demo     # по желанию — демо-данные
```

Интерфейс — `http://сервер:8080/`. Сервис скоринга работает отдельным контейнером без состояния (А-1, Р-1). Его можно масштабировать: `docker compose up -d --scale scoring=3`. Наружу он не публикуется, а запросы без ключа `SCORING_KEY` отклоняет.

**HTTPS (Б-1):** задайте `DOMAIN` в `.env` и запустите `docker compose --profile https up -d`. Caddy получит сертификат сам.

**Готовые образы:** раскомментируйте в `.env` строки `IMAGE_PREFIX` и `TAG`, затем `docker compose pull && docker compose up -d`.

### Из исходников

```
cd frontend && npm ci && npm run build      # интерфейс собирается в backend/creditdss/static
cd ../backend && pip install -e ".[dev]"
creditdss demo
creditdss run                                # http://127.0.0.1:8000/, API — /api/docs
```

Отдельный сервис скоринга: `creditdss scoring --port 8001` и `CREDITDSS_SCORING_URL=http://127.0.0.1:8001` у основного сервера.

## Настройки

Переменные окружения с префиксом `CREDITDSS_` или файл `.env`:

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | `postgresql+psycopg://user:pass@host:5432/credit_db`; пусто — SQLite в `data/creditdss.db` |
| `DATA_DIR` | папка данных: документы, резервные копии, ключ входа |
| `SECRET_KEY` | ключ подписи токенов; пусто — создаётся случайный в `data/secret.key` |
| `SCORING_URL`, `SCORING_KEY` | адрес и ключ отдельного сервиса скоринга; пусто — расчёт в процессе сервера |
| `LDAP_URL`, `LDAP_DOMAIN` | вход через Active Directory (В-1); роль и лимит берутся из учётной записи в системе |
| `ABS_API_KEY` | ключ, с которым АБС передаёт сведения об обслуживании кредитов |
| `MAX_UPLOAD_MB` | максимальный размер документа, по умолчанию 20 (П-3) |
| `SSL_CERTFILE`, `SSL_KEYFILE` | HTTPS прямо в сервере |
| `HOST`, `PORT` | адрес и порт веб-сервера |
| `SCHEDULER_ENABLED` | планировщик внутри веб-сервера; в Docker — отдельный сервис |

Параметры, которые меняются в интерфейсе («Администрирование → Параметры»): режим интеграции с БКИ и АБС (встроенный имитатор или HTTP API), адреса API, число и интервал повторов запроса в БКИ, пороги оповещений мониторинга, срок действия согласий, минимальная длина комментария к решению.

## Пользователи и роли (С-17)

«Администрирование → Пользователи и роли». Роли:

- **кредитный специалист**;
- **андеррайтер** — с лимитом полномочий в рублях;
- **руководитель кредитного отдела** — кредитный комитет; лимит обычно не задаётся;
- **риск-аналитик**;
- **администратор** — управляет системой, но к заявкам и персональным данным клиентов доступа не имеет.

Из командной строки: `creditdss create-user login пароль underwriter --name "ФИО" --limit 700000`.

## Журналы

- **Журнал аудита (С-18)** — все действия пользователей с данными: вход, создание и изменение заявок, решения, просмотр документов, изменения справочников, параметров и методики. В журнале видны изменённые значения «было → стало». Изменить или удалить записи нельзя: это запрещают триггеры СУБД. Выгрузка в XLSX.
- **Журнал обмена** — запросы в БКИ и АБС, обращения к сервису скоринга, уведомления клиентов, задачи планировщика.

## Резервное копирование (Н-1)

Копия создаётся каждый день в 02:00, хранятся 14 последних (`data/backup`). Вручную: «Администрирование → Резервные копии» или `creditdss backup`.

Восстановление — при остановленной программе:

```
creditdss restore creditdss-20261026-020000.db      # SQLite
docker compose stop api scheduler scoring
docker compose run --rm api creditdss restore creditdss-20261026-020000.dump --yes
docker compose start api scheduler scoring
```

Перед восстановлением текущее состояние сохраняется копией `…-before-restore`. После восстановления схема БД обновляется до текущей версии программы.

## Планировщик

| Задача | Когда |
|---|---|
| Повторные запросы в БКИ и АБС (С-3) | каждую минуту — заявки, у которых подошло время повтора |
| Мониторинг методики за прошлый месяц (С-15) | 1-го числа в 04:00 |
| Резервная копия | ежедневно в 02:00 |

## Персональные данные (Б-1, 152-ФЗ)

- Система предназначена для размещения во внутреннем контуре; доступ к данным разграничен по ролям.
- Риск-аналитик видит клиентов обезличенными.
- Каналы связи защищаются HTTPS.
- Запрос в БКИ без действующего согласия клиента невозможен.
- Документы хранятся в `data/documents`; их просмотр фиксируется в журнале аудита.
