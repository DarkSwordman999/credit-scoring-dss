# СППР «Кредитный скоринг» — оценка кредитоспособности физических лиц

**Тема:** «Разработка информационной системы поддержки принятия решений для оценки кредитоспособности физических лиц».

В репозитории — сама система и результаты практических работ по курсу «Программная инженерия» (ТулГУ, ИПМКН). По работам выполнены обследование и анализ осуществимости, требования и ТЗ по ГОСТ 34.602-89, функциональная (IDEF0, IDEF3) и объектная (UML) модели и план проекта. Затем система реализована по этому ТЗ: веб-приложение для всех ролей, REST API, отдельный сервис скоринга, интеграция с БКИ и АБС.

> **Ветки и редакции.**
> - `main` — **полная редакция** для отдела розничного кредитования банка (релизы `v*`).
> - [`coursework`](../../tree/coursework) — **базовая редакция** для небольшой кредитной организации с одним специалистом (релизы `basic-v*`).
> - [`ml`](../../tree/ml) — задел для ВКР: модели машинного обучения. В `main` машинное обучение не используется: оценка выполняется экспертной скоринговой картой — базовой методикой из ТЗ.
>
> Ветки не сливаются: у каждой свой цикл выпуска.

## Идея системы

Банк получает заявку на потребительский кредит. Система:

1. сама собирает данные: анкету, кредитный отчёт БКИ, сведения из АБС;
2. проверяет паспорт и стоп-листы, формальные стоп-факторы кредитной политики;
3. рассчитывает показатель долговой нагрузки (ПДН) и **вероятность дефолта (PD)**;
4. присваивает класс риска и рекомендует решение и условия кредита;
5. **объясняет оценку**: показывает пять факторов, сильнее всего повысивших риск, и пять, сильнее всего его снизивших.

Решение принимает андеррайтер. Суммы сверх его лимита полномочий уходят на кредитный комитет.

| Подсистема | Что реализовано |
|---|---|
| Приём и учёт заявок | Анкета с подстановкой клиента по паспорту, согласия (152-ФЗ, 218-ФЗ), копии документов, 11 состояний заявки по ПР 7-8 |
| Сбор и верификация данных | Параллельные запросы в БКИ и АБС, проверка паспорта, перечня Росфинмониторинга и стоп-листа, повторы при недоступности бюро |
| Скоринг | 40 признаков, 13 стоп-факторов, скоринговая карта из 14 характеристик, PD, класс риска A–E, ПДН, вклад факторов; отдельный сервис `POST /score` и резервная методика |
| Поддержка принятия решений | Рекомендация по матрице «класс риска × ПДН», решение с обязательным обоснованием расхождений, лимиты полномочий, кредитный комитет, уведомление клиента с причинами отказа, передача в АБС |
| Мониторинг и версии методики | Реестр версий, проверка на созревших кредитах (ROC AUC, Gini, KS), утверждение и публикация, откат, ежемесячные PSI и Gini с оповещениями |
| Заёмщики и портфель | Реестр клиентов и карточка заёмщика (все заявки с решениями и причинами, кредиты, кредитная история), кредитный портфель с итогами и сравнением прогноза PD с фактом по классам риска |
| Отчётность | Заявки, решения и уровень одобрения, качество портфеля и методики — с выгрузкой в XLSX и PDF |
| Администрирование | Пять ролей, справочники кредитной политики, неизменяемый журнал аудита, журнал обмена, резервные копии, вход через Active Directory, просмотр таблиц БД со скрытием персональных данных |

## Запуск

**Windows без установки.** Скачайте `CreditDSS-<версия>-windows-x64.zip` со страницы [Releases](../../releases), распакуйте и запустите `КредитныйСкоринг.exe`. При первом запуске программа предложит загрузить демо-данные.

**Сервер в Docker** (PostgreSQL, API, сервис скоринга, планировщик, nginx с интерфейсом):

```
cd deploy
cp .env.example .env      # задайте пароли и ключ сервиса скоринга
docker compose up -d --build
docker compose exec api creditdss demo
```

**Из исходников** (Python 3.12, Node.js 22):

```
cd frontend && npm ci && npm run build      # интерфейс собирается в backend/creditdss/static
cd ../backend && pip install -e ".[dev]"
creditdss demo        # демо-данные: 30 месяцев истории, ~6 000 заявок, ~3 700 кредитов
creditdss run         # http://127.0.0.1:8000/, API — /api/docs
```

Вход: `admin`/`admin`. Демо-пользователи с паролем `demo`:

- `officer` — кредитный специалист;
- `underwriter` — андеррайтер, лимит 1 млн руб.;
- `underwriter2` — андеррайтер, лимит 500 тыс. руб.;
- `head` — руководитель отдела;
- `analyst` — риск-аналитик.

Больше всего видит `head`. Администратор заявки и персональные данные клиентов не видит — это разделение полномочий; зато на его главной странице есть список демо-пользователей и кнопка «Войти под этой ролью».

Документация:

- [руководство пользователя](docs/USER_GUIDE.md);
- [руководство администратора](docs/ADMIN_GUIDE.md);
- [интеграция с БКИ, АБС и сервисом скоринга](docs/INTEGRATION.md);

- `pytest` в `backend` — модульные и API-тесты на SQLite и PostgreSQL;
- `tests_e2e` — сквозные тесты интерфейса на Playwright.

Тесты запускаются в GitHub Actions при каждом push; релиз собирается по тегу `v*`.

## Методика оценки

Экспертная скоринговая карта: баллы по 14 характеристикам заёмщика, балл переводится в PD стандартной калибровкой (600 баллов ↔ шансы 50:1, удвоение каждые 20 баллов). Риск-аналитик меняет баллы в новых версиях и проверяет их на кредитах, по которым прошло 12 месяцев (целевая переменная — просрочка 90+ дней). Версия хуже действующей по Gini не публикуется.

На демо-истории действующая версия даёт ROC AUC 0,79 (Gini 0,58) при требовании ТЗ не ниже 0,75. Подробнее — в [docs/METHODOLOGY.md](docs/METHODOLOGY.md).

## Структура репозитория

```
backend/     сервер: FastAPI, SQLAlchemy, миграции Alembic, сервис скоринга, планировщик, тесты
frontend/    веб-интерфейс АРМ: React + TypeScript
deploy/      Docker Compose: PostgreSQL, backend-api, scoring-service, scheduler, web-frontend
packaging/   сборка Windows-версии (PyInstaller)
docs/        руководства пользователя и администратора, интеграция, методика, описание релиза
reports/     отчёты по практическим работам (DOCX + PDF)
diagrams/    диаграммы: IDEF0, IDEF3, VORD, ER, UML, сетевой график, Гант
tools/       генератор отчётов (python-docx + MS Word) — исходники текста и диаграмм
```

Отчёты собираются генератором из `tools/report_generator` (`python build.py`). Ему нужны Windows, MS Word, Java 11+ и [`plantuml.jar`](https://github.com/plantuml/plantuml/releases), положенный рядом со скриптами. Данные титульного листа задаются в `config.py`.
